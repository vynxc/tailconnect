# Tailconnect v0.3.0

Permanent pairing codes, saved agent pairing, and the dark Material 3 UI from
v0.2.0.

## Highlights

### Persistent phone code

The Android app can now keep the same 13-character code across service and app
restarts:

- **Keep this code across restarts** is enabled by default.
- The secret is stored with Android Keystore AES-GCM, not in plaintext
  preferences, logs, or backups.
- **Rotate** clears the saved key and starts a new session.
- Unchecking persistence clears the saved code and returns to ephemeral codes.
- The server reuses the code's DERP-region residue and chooses the nearest
  official Tailcat region with that residue, so the code survives a restart even
  if the nearest region changes.

### Saved agent pairing

The agent can save the code once and reconnect without repeating it:

```bash
tailconnect save ABCD-EFGH-JKMN3
tailconnect agent --name workstation --socks 127.0.0.1:1080
tailconnect forget
```

The saved code is stored in the platform user-config directory:

```text
$XDG_CONFIG_HOME/tailconnect/pair.json
```

with mode `0600`.

### Still no VPN

No `VpnService`, no TUN, no route/DNS changes, no VPN permission. Only explicitly
forwarded traffic uses the tunnel.

### Dark Material 3 UI

The app uses `Theme.Material3.Dark.NoActionBar`, Material 3 color roles,
Material cards, filled/outlined buttons, and a Material checkbox. The code card
now shows `PAIR CODE · PERSISTENT` or `PAIR CODE · SESSION`, and includes a
**Rotate** action.

### Automatic context from v0.2.0

Unchanged and included:

- phone model/app version, network, LAN prefix, gateway, DNS
- reverse service ports and localhost URLs
- mDNS-discovered wireless-debugging endpoints
- auto-created local ADB forwards and ready-to-run `adb connect`/`adb pair`
  commands
- other mDNS services on the phone LAN

## Verification

- `go test -race ./...` and `go vet ./...` pass.
- `./scripts/e2e-local.sh` passes forward, SOCKS5, and reverse-service paths over
  official Tailcat DERP.
- Persistent-code server tested with `serve --code`; the same code and region
  residue were reused across restarts.
- `tailconnect save` + `tailconnect agent` without `--code` connected using the
  saved code.
- Android lint: 0 errors.
- APK manifest verified: no `VpnService`, no `BIND_VPN_SERVICE`, not debuggable,
  arm64-v8a + x86_64 payloads.
- APK embedded arm64 payload hash matches the released
  `tailconnect-android-arm64` binary.

## Known limitations

- A persistent code is a long-lived bearer credential. Anyone with the code can
  connect while the phone service is running. Use **Rotate** if it leaks.
- The persistent code is tied to its DERP-region residue. If that residue is
  removed from the official DERP map, rotate the code.
- The v0.3.0 APK was built and linted, but the new persistent-code UI has not
  been visually tested on a physical device yet.
- mDNS discovery is best-effort through Android `NsdManager`; SSDP/UPnP is not
  implemented yet.
- Agent-side SOCKS and `--forward` are TCP-only.
- IPv4 LAN prefixes only.
