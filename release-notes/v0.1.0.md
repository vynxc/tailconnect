# Tailconnect v0.1.0

First alpha release of a serverless Tailcat pair tunnel.

Tailconnect pairs an Android phone with an agent through a 13-character code.
It is deliberately **not a VPN**: no `VpnService`, no TUN, no route or DNS
changes, and no Android VPN permission. Only traffic explicitly sent through
`tailconnect` uses the tunnel.

## What works

- **Agent → phone LAN:** local SOCKS5 proxy and explicit TCP forwards into the
  phone's current Wi-Fi/Ethernet network, for TVs, routers, NAS boxes, and
  wireless ADB.
- **Phone → agent services:** the agent publishes `id=host:port` services; the
  phone app creates `http://localhost:<port>` bookmarks over a smux reverse
  proxy on the same Tailcat tunnel.
- **One 13-character code:** 12-character secret plus a DERP-region residue.
  Argon2id (3 passes, 64 MiB, 1 thread, 96 bytes) derives a server key, a
  WireGuard PSK, and a client key. The server allowlists the client key.
- **Serverless:** no account, database, short-link service, or coordination
  server. Only the official Tailcat DERP map and relays are used. Direct P2P is
  preferred; DERP is the fallback.
- **Reconnect:** the agent reconnects after the phone-side server restarts with
  the same code.
- **Android app:** native Activity + `specialUse` foreground service; detects
  the active Wi-Fi/Ethernet IPv4 subnet; shows the code, shareable link,
  connected agent, and service bookmarks. Window is `FLAG_SECURE`.
- **Agent skill:** `skills/tailconnect/SKILL.md` with pairing, SOCKS, ADB, TV,
  and `--expose` workflows.

## Quick start

```bash
chmod +x tailconnect-linux-amd64
./tailconnect-linux-amd64 serve --allow 192.168.1.0/24
```

On the agent:

```bash
./tailconnect-linux-amd64 agent --code ABCD-EFGH-JKMNP \
  --name workstation \
  --socks 127.0.0.1:1080 \
  --expose web=127.0.0.1:3000
```

Wireless ADB:

```bash
./tailconnect-linux-amd64 agent --code ABCD-EFGH-JKMNP \
  --forward 5555=192.168.1.50:5555
adb connect 127.0.0.1:5555
```

Install the APK:

```bash
adb install -r Tailconnect-0.1.0.apk
```

## Verification

- `go test ./...` and `go test -race ./...` pass.
- `go vet ./...` passes.
- `./scripts/e2e-local.sh` passed all three paths over official Tailcat DERP:
  explicit forward, SOCKS5, and smux reverse service.
- Release APK manifest verified: no `VpnService`, no `BIND_VPN_SERVICE`, not
  debuggable, arm64-v8a + x86_64 payloads.
- APK payload hash matches the released `tailconnect-android-arm64` Go binary
  before packaging.

Android runtime still needs real-device validation. The build host has no KVM,
so the x86_64 emulator could not boot.

## Known limitations

- 13-character codes are session credentials; stop the service to rotate them.
- Agent-side SOCKS and `--forward` are TCP-only. The phone server has unicast
  UDP forwarding, but the CLI does not expose UDP forwards yet.
- mDNS/SSDP discovery is not implemented; use known IPs and ports.
- IPv4 LAN prefixes only.
- HTTPS services exposed through `localhost` may show certificate warnings.
- Official Tailcat DERP relays are rate-limited and best-effort.
