# Tailconnect v0.2.0

The phone now tells the agent what it needs automatically, and the Android UI is
a dark Material 3 surface.

## Highlights

### Automatic phone context

As soon as an agent connects, the phone sends a `PhoneContext` over the same
Tailcat tunnel:

- phone model and app version
- active network type, interface, phone IPv4 address, LAN prefix, gateway, DNS
- reverse service IDs, labels, assigned localhost ports, and URLs
- wireless-debugging endpoints discovered over mDNS
- other mDNS services on the phone LAN: Google Cast, AirPlay, HTTP/HTTPS,
  printers, SMB, SSH, workstations

The agent prints this context and can use it without asking for the same values
again.

### Automatic wireless ADB

When the phone advertises `_adb-tls-connect._tcp` or `_adb-tls-pairing._tcp`, the
agent creates local `127.0.0.1` forwards and prints ready-to-run commands:

```text
adb connect 127.0.0.1:42619 -> 192.168.1.50:5555
adb pair 127.0.0.1:44463   -> 192.168.1.50:37123 (pairing code required)
```

Disable with `--no-auto-adb`.

### Dark Material 3 UI

The Android app now uses `Theme.Material3.Dark.NoActionBar`, Material 3 color
roles, cards, filled/outlined Material buttons, and a Material checkbox. It is
still not a VPN: the manifest contains no `VpnService`, no `BIND_VPN_SERVICE`,
and no VPN permission.

### Real-device test

Through the phone tunnel, the agent reached a Roku Express on the phone's LAN:

- Roku ECP `/query/device-info` and `/query/active-app` worked
- the debug console showed a sideloaded development app, `VIPTV`, id `dev`,
  version 1.9.5, entry `pkg:/source/main.brs`
- Roku ECP `/query/apps` was blocked by the device's Limited mode
- the Roku dev web interface rejected the provided credentials with `401`, so
  full package inspection was not available

## Verification

- `go test -race ./...` and `go vet ./...` pass.
- `./scripts/e2e-local.sh` passes forward, SOCKS5, and reverse-service paths over
  official Tailcat DERP.
- PhoneContext and automatic ADB forward behavior tested locally with a
  simulated discovery update.
- Android lint: 0 errors.
- APK manifest verified: no `VpnService`, no `BIND_VPN_SERVICE`, not debuggable,
  arm64-v8a + x86_64 payloads.
- APK embedded arm64 payload hash matches the released
  `tailconnect-android-arm64` binary.

## Known limitations

- The v0.2.0 APK was built and linted, but the new Material 3 UI has not been
  visually tested on a physical device yet. The Roku test used the previously
  installed v0.1.0 Android app for the tunnel.
- mDNS discovery is best-effort through Android `NsdManager`. SSDP/UPnP is not
  implemented yet.
- Agent-side SOCKS and `--forward` are TCP-only. The phone server has unicast
  UDP forwarding, but the CLI does not expose UDP forwards yet.
- IPv4 LAN prefixes only.
- Roku ECP is in Limited mode, and the provided dev web credentials returned 401.
- 13-character codes are session credentials; stop the service to rotate them.
